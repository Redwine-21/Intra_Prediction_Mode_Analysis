# Project 2502M - AV1/VVC Intra Prediction Mode Analysis

Project 2502M is a live demo and analysis pipeline for comparing intra
prediction modes in AV1 and VVC/H.266. The pipeline takes an input video,
encodes it with modified AV1 and VVC encoders, reads the real CSV statistics
dumped by those encoders, and generates comparison reports and visualizations.

## Objectives

- Run SVT-AV1 and VVenC on the same input video.
- Collect real CSV dumps from modified encoder source code.
- Validate both CSV files against a shared schema.
- Normalize AV1 blocks and VVC CUs/PUs onto a fixed 64x64 grid for fairer
  spatial comparison.
- Generate reports, JSON summaries, bitstreams, and visual plots.
- Provide a Streamlit interface for uploading or generating videos and viewing
  the analysis results.

## System Requirements

The following components must be available:

- Linux shell with `bash`
- Python 3.10 or newer
- `ffmpeg` and `ffprobe`
- A modified `SvtAv1EncApp` binary that writes `av1_stats.csv`
- A modified `vvencapp` binary that writes `vvc_intra_modes.csv`
- Required SVT-AV1 shared libraries, for example `libSvtAv1Enc.so*`

Important: this project does not create synthetic or content-derived CSV data.
If the encoders do not write real CSV files, the pipeline stops with an error.

## Run the Pipeline With an Existing Video

```bash
./run_pipeline.sh \
  --input input.mp4 \
  --output-dir results \
  --width 1280 \
  --height 720 \
  --fps 30 \
  --frames 10 \
  --qp 30
```

If `--width` and `--height` are not provided, the script tries to detect the
input resolution with `ffprobe`. If detection fails, it falls back to
`1920x1080`.

## Run the Pipeline With a Generated Test Video


## Input CSV Schema

Both encoder CSV files must contain at least seven columns in this order:

```text
frame_num,frame_type,x,y,width,height,intra_mode
```

Column meanings:

- `frame_num`: frame index.
- `frame_type`: `I`, `P`, or `B`.
- `x`, `y`: block/PU position.
- `width`, `height`: block/PU size.
- `intra_mode`: intra prediction mode ID.

The parser skips header rows and comment rows starting with `#`.

## Pipeline Flow

1. Remove old CSV files and previous outputs.
2. Prepare the input video, raw YUV file, or FFmpeg-generated test source.
3. Convert the input to YUV 4:2:0 when needed.
4. Run `SvtAv1EncApp` and require it to write `av1_stats.csv`.
5. Run `vvencapp` and require it to write `vvc_intra_modes.csv`.
6. Validate that the CSV files contain the expected frames, valid block sizes,
   and valid frame types.
7. Run `intra_prediction_analysis.py` to generate statistics, plots, JSON, and
   text reports.

If VVenC writes CSV data for fewer frames than requested, the pipeline attempts
a real per-frame fallback: it runs VVenC once per frame, merges the resulting
CSV files, and remaps the frame indices. If the CSV is still missing or
incomplete, the pipeline fails.

## AV1/VVC Comparison Note

AV1 and VVC use different block, CU, and PU partitioning strategies, so raw CSV
row counts are not directly comparable as a fair metric. The analyzer therefore
normalizes both codecs onto a fixed 64x64 spatial grid. For each frame and each
grid cell, the dominant intra mode is selected. The normalized grid plots use
this representation to reduce partitioning bias.

## Common Issues

- `ffmpeg not found`: install FFmpeg on the system.
- `SvtAv1EncApp not found`: place the binary in the project root or add it to
  `PATH`.
- `vvencapp not found`: place the binary in the project root or add it to
  `PATH`.
- `Missing AV1 real CSV`: the SVT-AV1 binary is not the modified CSV-logging
  build.
- `Missing VVC real CSV`: the VVenC binary is not the modified CSV-logging
  build.
- SVT-AV1 shared library errors: check `libSvtAv1Enc.so*` and
  `LD_LIBRARY_PATH`.
